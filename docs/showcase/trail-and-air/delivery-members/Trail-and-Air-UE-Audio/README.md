# Trail & Air — original game audio kit

17 standalone assets for a walking/exploration prototype. All audio is original procedural synthesis generated by a typed DCC-MCP skill, assembled in a real REAPER 7.82 native project, and individually exported by its offline renderer through Gateway/CLI calls. No scene, game project, video, screenshot, recording, external sample or third-party instrument was used.

## Import into Unreal Engine

Import the 17 WAV files from `Audio/`. They are 48 kHz / 24-bit PCM.

- `footstep_stone_01..06`: mono soft gravel/stone variations.
- `footstep_grass_01..06`: mono grass/earth variations.
- `environment_soft_wind_foliage_loop`: stereo, 20 s seamless ambience bed.
- `music_sparse_tonal_loop`: stereo, 19.2 s / 8 bars / 100 BPM subtle tonal bed.
- `interaction_confirm`, `interaction_discovery`, `interaction_soft_impact`: mono one-shots.

`Audio/manifest.json` records exact frame lengths, loop markers, suggested playback gains, pitch/volume variation bounds and SHA256 values. Treat these gains as starting points, not a tested in-game mix. Footsteps should be driven by animation notifies/contact events with no immediate repeated variant. Use positional playback for mono footsteps/SFX; use non-spatial stereo beds for ambient/music loops. Footstep surface selection and timing require integration in your own project.

This package does not claim that events, spatialization, attenuation or a walkthrough have already been integrated or tested in Unreal. Subjective listening review is pending; audio input was unavailable in the authoring assistant runtime. Listen at a comfortable level, especially when auditioning the quiet ambience.

## Native validation and source

- 17 assets actually rendered through REAPER, then native RPP reopened.
- Every export matches the corresponding synthesized source PCM sample-for-sample: native renderer preserved length, channels, levels and loop boundaries.
- Zero clipped samples; both loops pass measured boundary-step/level/spectral checks. These checks do not replace listening.
- Delivery WAVs remove BWF/encoder metadata while preserving PCM bytes.
- `Trail-and-Air.rpp` and its relative `Audio/` files are editable native sources. The atlas places each asset in a separate region with no overlap or auto-fades.
- `Skills/` contains the tested typed synthesis/native-authoring skills. `Source/game_audio_pack.py` regenerates deterministic originals; `Validation/` records source and native-export checks.

The DCC-MCP adapter fixes used in this run are proposed in [REAPER PR #3](https://github.com/dcc-mcp/dcc-mcp-reaper/pull/3), commit `867ce6837c916aa7ca89a5cb14deae9869f09d00`. The adapter itself remains read-only; mutation/render operations use the additional included skills. The source generator requires Python 3.9+ and NumPy. The validated lane uses external reapy_boost with embedded Python configured in REAPER.

## Reproduce through DCC-MCP

1. Install a properly licensed REAPER host. The official Linux build supports the vendor-documented `NOGDK=1` custom libSwell option. A headless host is still a real running REAPER.
2. Configure the adapter external transport as documented in the linked PR. Add `Skills/` to `DCC_MCP_REAPER_SKILL_PATHS`; start the official adapter CLI and a local gateway.
3. Use inventory, scoped search, load-skill and describe before calls. From an empty clean project, call `reaper_game_audio__generate_pack` with a new output directory and `seed: 73`.
4. Call `reaper_game_audio__render_assets` with that directory. It creates the native per-asset renders and a validation record. Never overwrite existing renders; inspect partial progress before choosing a fresh destination.
5. Reopen the saved RPP through `reaper_stem_session__open_project`, audit it, and verify sample counts/format and hashes.
