# Native GIMP website preview

The website derivative was produced through the typed export_preview tool from a native GIMP duplicate. This directory preserves the six helper/fixture files, input files and revised binding used by the corrected native02 195-record run. It does not contain an installed adapter, source checkout or wheel.

The qualified master is duplicated here only to retain the unchanged fixture's input contract. It is byte-identical to gimp/native/gimp/seismic-lens-master.xcf; no second authoring version is implied.

## Reproduce

Follow REPRODUCE_WHEEL.md from this preview directory. Those build instructions are preserved verbatim from the source-only software handoff; its last paragraph describes that original handoff. This case companion adds the hash-bound fixture and artwork inputs. Obtain the official public base and apply the included reviewed patch into a new source/ directory, then reproduce the exact wheel under dist/. Install it into a separately prepared runtime; keep that runtime separate from the composition stage's earlier wheel. All 69 source hashes, 42 package files and the wheel digest must match candidate-binding.json. Do not change these guards when a build differs.

With the documented GIMP 3.0.4 graphical environment and exact runtime active, run:

    /path/to/preview-runtime/bin/python -B reproduce/verify_preview.py --check
    /path/to/preview-runtime/bin/python -B reproduce/verify_preview.py --run --run-root /path/to/new/preview-run

The helper owns a fresh GIMP host, opens a copied master, produces the 1600×1000 PNG, compares original full-size RGBA and editable state, natively reopens the preview and tests small transparent/no-upscale/aspect-rounding cases. It refuses an existing output root. Files are generated by actual discovered MCP calls; Python only orchestrates and reads verification data.

The candidate commit in the binding is a historical local qualification identity, not a public checkout instruction. Use the exact public base plus included patch. The native_validation=NOT_EXECUTED label in the original sealed binding records its pre-execution state; the later completed proof is ../evidence/native-preview-validation.json and retains that binding's hash. No original proof was rewritten.

seal_candidate.py is included solely because it is part of the historical hash-bound six-file inventory. It is a qualification-maintenance script that can rewrite bindings. It is not part of the reproduction commands and must not be run to bypass a failed check.

## Limits and rights

Native source admission is bounded to the tool's documented RGB/RGBA U8 format, image/layer/metadata/filter limits. File publication assumes a trusted isolated host and caller-controlled roots; it does not establish resistance to hostile same-user mutation. Windows native behavior is unqualified. Context/source cleanup and staging are checked, but a reported cleanup error after publication must be treated as an existing committed output rather than safe-to-repeat failure.

The verbatim UPSTREAM-ADAPTER-LICENSE.txt applies to the separately identified adapter software increment and upstream code only. It makes no new grant over the case artwork, native assets, original data or new showcase production recipe. Top-level RIGHTS.md governs those case materials.

## Verification-only correction

The first verification helper looked for image_id outside the actual context.image envelope. Its before/after comparison could therefore compare two missing values; that comparison receives no validation credit. The original trace remains preserved. A separate explicit audit of its six actual responses found the reported IDs unchanged, but that does not repair the old assertion.

This package supplies the corrected helper: it requires completed-result/context/image structure and a positive non-boolean integer image ID equal to the intended source before and after each preview. It also protects cleanup finalization from diagnostic/receipt failures within the reviewed cleanup tail. The corrected run passed all native checks and recorded three explicit ID pairs. It does not claim every early-startup or pathological cleanup failure is covered.

The adapter, wheel and artwork inputs did not change. The accepted website PNG is retained: compared with the fresh native02 output, every chunk except generated tIME and all decoded RGBA pixels are identical. The current proof names both image hashes. Historical native01 output and its original helper/binding are not silently relabeled as native02.
