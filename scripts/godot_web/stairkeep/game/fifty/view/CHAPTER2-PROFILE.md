# Chapters 1–2 preview entry

The additional current scene is `res://fifty/view/chapter2.tscn`, in the existing
Godot project. It extends the available journey from normal floor-1 startup
through floor 20; it does not create a resource grant or a jump-start on floor
11. The original `preview.tscn` file still selects the first-chapter defaults.
Neither this view change nor this document changes an already delivered Web
ZIP, source ZIP, evidence inventory or packaging measurement.

The shared presenter has three exported settings:

| Setting | Default first chapter | Chapters 1–2 scene |
|---|---|---|
| `content_path` | `res://fifty/data/content.json` | `res://fifty/data/chapter2-content.json` |
| `slot_id` | `first-chapter` | `chapter2-preview` |
| `profile_label` | `First chapter` | `Chapters 1–2` |

Every load-content path, including candidate new-run and candidate save-load
validation, receives `content_path`. The presenter reads the validated runtime's
`profile_info()` for content identity, authored count, target count, available
floor IDs and unmade range. It does not infer twenty floors from the filename
or make the original scene say twenty. Mode selection remains explicitly empty
until the player chooses Classic or Practice.

The expected read-only profile keys are `content_id`, `authored_count`,
`target_count`, `authored_floors`, `not_authored_floors`, `checkpoint_floors`,
and `slice_goal_object_id`. Recovery choices still use only the complete
checkpoints actually captured in the accepted snapshot, never a predicted
future checkpoint from the profile description.

The save owner selects a supported chapter namespace from the runtime identity;
the view only calls `write_slot(runtime, slot_id)` and
`load_slot(candidate, slot_id)`. Mode isolation, failed-Classic current-session
guards, accepted-snapshot seed synchronization and failed-confirmation cancel
behavior remain in place. No old slot is migrated. The original first-chapter
packages retain their own frozen source/save behavior.

For the new profile, `flags.relay_lit` on F10 produces a visible **Chapter 1
milestone** in the scope label while play may continue toward F20. Only the
runtime's `slice_complete` produces the slice-complete modal. A failed snapshot
takes precedence over either completion notice. Completion is still a slice of
the fifty-floor target; `campaign_complete` and the core victory flag are not
assigned by the view. The new scope explicitly says **21–50 are not yet built**;
the first-chapter profile continues to say **11–50 are not yet built**.

Floor/object `name_en` and event `text_en` are used when supplied. Original
first-chapter names and original event text remain fallbacks. NPC fallback names
are tied to the two original NPC IDs, so new NPCs cannot become the old
lightkeeper merely because they are above floor 1.

The new `journal_entries` array is read-only presentation data. Each row uses
its supplied `floor`, `text_en`/`text` and `status_flag`, reading the latter from
the accepted snapshot's flags. This displays progress; it neither evaluates nor
executes event effects. Actual rewards remain the first eligible runtime event's
typed finite grants. Older content without this metadata retains the existing
first-chapter return-visit display.

The existing ten terrain tints cycle safely above floor 10. The first ten colors,
licensed Kenney textures, MIT isometric TileSet projection, native resource
icons, damage cards and story markers are retained. No images, fonts or other
large resources are acquired or generated by this change.
