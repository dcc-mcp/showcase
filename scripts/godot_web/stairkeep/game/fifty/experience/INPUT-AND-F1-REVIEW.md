## 确定差异与实际修正

| 项目 | 原稿与旧源码的差异 | 本轮候选实现 | 尚待真实检查 |
|---|---|---|---|
| 方向 | 旧 W/↑ 是 grid(0,-1)，实际画面↗；A/←是↖，S/↓是↙，D/→是↘ | 用实际 projected_cell_center 的邻格位移解析屏幕意图。四斜向按钮、方向组合键；同分两格由玩家选择，不代走两步、不跳格、不遇墙降级拐弯 | 四方向/四斜向、短按/组合时序、墙角 |
| 选中对象 | 鼠标高亮可移到 B，右侧卡与操作仍绑定 A | 已选目标时高亮固定该目标，明确点击才更换；物件再点一次或 E/空格确认 | 高处门/敌人/资源点击、遮挡下目标 |
| 路径停止 | 路径锁先于 Esc，使长路径无法暂停 | Esc 只请求取消；当前权威动作及动画结束后，不再提交下一格，再进入暂停 | 中间格、终点、换层动画、对话中取消 |
| 尺度与布局 | F1 是15×15数据框、49可走格；旧取景已排除远处空白，但长廊仍整层缩入视窗 | 近看1.6倍、角色中间50%安全区、可切整层总览；使用 Control.clip_contents 限定地图视窗，投影不旋转，不改地图拓扑 | 地块实际像素、相机边缘、总览往返与HUD遮挡 |
| 墙与地形 | 碎矮块/随机柱使支路边界模糊，出生后方易像开放出口 | 墙帽按完整地块连续拼接，只露临路前面；F1不放随机高柱；暖地砖与深色墙区分 | 连续墙肩、前景遮挡、拾取物与脚底可见 |
| 门 | 旧版统一 N；canonical F1 两门 N 本身不构成错误，旋转后的变体才需换轴 | 根据运行时已变换邻格选 N/E；开/闭共用各方向锚点，不按展开门叶 bbox 重居中；原同色钥匙规则不变 | 开闭门框不跳位、钥匙只扣一次、回访仍开 |
| 出口 | 原稿有明确终端门阶 | F1 上梯加原 CC0 门廊框并保留中文目标；后方墙仍封闭，不画假出口 | F1→F2→F3与返回、进入/返回触发和提示 |

官方组件的 TileSet 为 ISOMETRIC / DIAMOND_DOWN，有效 tile_size=256×128。缩放前的四邻位移分别是↖(-128,-64)、↗(128,-64)、↙(-128,64)、↘(128,64)。相机仅统一缩放/平移，因此不存在一次四邻格动作的正上/正左邻格。新输入解析先比较全部几何邻格，再检查最佳方向的可走性；墙不能让一个斜向输入转为次佳方向。D4 已反映在运行时坐标里，不再旋转键表。

输入变化是表现层命令选择：一次确认仍只调用原 `move/interact/use_stairs/buy` 一次。没有新增自动战斗/开门/拾取、隐式两格路径或数据资源。70ms组合键收集窗口用于在移动前形成双键；点击、菜单和 Esc 会取消尚未提交的键盘意图。此窗口手感仍须实际输入确认。

## F1 代表层与保护

canonical F1 出生 `(7,13)`，两黄门 `(3,4)/(11,4)` 的侧邻均已有墙；上梯 `(7,1)` 为单入口终端，出生后方是墙。上述坐标仅用于对照，不代表用户当前 seed/D4 变体。渲染器从运行时邻格推门方向，不按这些坐标或门 ID 写死。F1 没有商店，商店验收必须到有商店的原楼层。

F1内容、其余各层独立地图、怪位、钥匙/经济、事件、D4、战斗、完整存档模块均沿用冻结首章原字节。本轮不把所有楼层改成同一布局，也不扩层。共用显示机制以F1为代表验证，不能将源码审查称为其他楼层已玩。
