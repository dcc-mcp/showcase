# 键盘体验03：已接源码，实际操作待验

这轮修复体验02源码审查发现的三个问题：持键不续步、动画期间丢键，以及70ms后重新读取物理键会丢失短按组合。只修改输入与呈现适配层；规则、一步一格的行动成本、地图、经济、战斗、D4及存档保持首章原字节。没有启动 Godot、导出 Web 或更新18764。

## 方向与续步规则

沿用实际等距投影，四邻格在画面上是左上、右上、左下、右下，没有正上方的相邻格：

| 屏幕输入 | 候选网格增量 |
| --- | --- |
| ↑ / W | 左上 `[-1,0]`、右上 `[0,-1]` |
| ↓ / S | 左下 `[0,1]`、右下 `[1,0]` |
| ← / A | 左上 `[-1,0]`、左下 `[0,1]` |
| → / D | 右上 `[0,-1]`、右下 `[1,0]` |
| ↑+← / W+A | 左上 `[-1,0]` |
| ↑+→ / W+D | 右上 `[0,-1]` |
| ↓+← / S+A | 左下 `[0,1]` |
| ↓+→ / S+D | 右下 `[1,0]` |

只在与输入夹角最小的几何候选中检查可走性。一个可走邻格就走一步，两个就显示一次选择，全部阻挡就停止；不会改走夹角更大的方向。选择斜向后按住会锁定该网格方向，不在后续每格重新询问。遇墙停止，不自动拐弯。需要转角时改变按键；没有两格合并、穿墙、对角网格跳步或新增行动奖励。运行时坐标已经经过D4，不再次旋转键位表。

初次真实按下收集至多70ms的重叠组合；完整短按在松键后仍保留一次。首次步派发后240ms才可续步，此后每次实际派发间隔至少180ms，动画忙碌时等待，不补发迟到次数。兼容的加键／部分松键保持方向锁和时限，不额外加速。W+S、A+D为相反输入；它们恢复剩余方向时重新等待70ms，提前全部松开不会产生幽灵步。

动画期间最多保留一个最新意图，保存的是方向而非旧坐标；下一格从当前状态重新计算。松键停止持续步进，但已经完成的短按可以在当前格结束后执行一次。若要取消这一步，按 Esc。操作系统 keydown repeat 不产生队列；同一帧最多提交一步。

## 停止与交互

Esc、鼠标／触摸、GUI获焦、窗口失焦、弹窗、手动确认、购买、存读档和换层会硬取消持键及待执行意图。已提交的当前格结束后停，取消不会提前解除该步的busy锁。若方向键还按着，必须全部松开后重新真实按下；窗口或UI归还焦点不能自动恢复移动。

走向门、敌人、楼梯、商店和道具时先停并查看目标。确认必须是之后新的 E／空格／Enter 或点击；忙碌时的确认不会缓存，也不会因持键重复开门、战斗或购买。同一帧选中并确认被拦截。GUI焦点检查只作用于键盘，不禁用显式UI按钮。

## 可复现检查及边界

从 `game` 目录运行，不启动引擎：

```powershell
python -B fifty/experience/tests/keyboard_reference.py -v
python -B fifty/experience/tests/test_keyboard_wiring.py -v
```

独立手写 golden 语料有34个命名trace、39个展开trace、272个事件。41项Python参考／策略测试和13项静态接线检查通过。参考实现未读取生产控制器；这些结果不能称为生产GDScript运行通过。静态检查覆盖唯一按键生产者、单一驱动、释放不在GUI处理前派发、焦点取消、单格busy、确认分离及旧timer驱动移除。
