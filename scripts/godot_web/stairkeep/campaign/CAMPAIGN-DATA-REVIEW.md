每层在暂不阻挡可交互对象时，全部可走格处于同一连通分量；从格子中提取的房间走廊边与该层 `topology.edges` 全部一致。21 个坐标边集合互不相同，21 份实际格子布局也互不相同。无标号树经中心剥离与 AHU 根树规范化得到 8 类：

这说明采用了有复用的房间树语法，不说明 21 层在固定坐标、入口、门、商店与资源决策上相同。把它写成“21 种互不同构树”会夸大；写成“21 份固定坐标布局，8 种无标号树形”准确。

## 具体发现：首店先买铸甲或补给会形成资源死局

相关代码：`tools/build_campaign.py:110` 的商店价格、`:151` 的首层高防重卫；购买入口见 `scripts/base_rules.gd:210` 和 `scripts/campaign_rules.gd:190`。当前购买是直接执行，没有针对这个首店必需投资的事前约束。

`f01_guard` 防御为 28，格子 `[2,4]` 是必经割点。挡住该格并将其他对象视为可通过后，能到达的所有资源给出一个宽松上界：不购买磨刃时攻击最多 26，金币最多 40。金币上界包括入口 16、巡卫奖励 14，以及花黄色钥匙进入防御房的 10；攻击房及其他金币来源都在重卫之后。这个上界已经忽略部分实际花费，因而可以用来证明不足。

- 先买铸甲花 28，之后金币即使搜尽也至多剩 12。
- 先买补给花 24，之后金币即使搜尽也至多剩 16。
- 磨刃需要 28 金；上述两种购买都不增加攻击，故之后仍无法达到穿透重卫的攻击条件，也无法攒回磨刃价格。

四条作者 witness 的第一次购买全部是 `buy:f01_shop/edge`，因此四条成功路线本身不覆盖这个负例。这不是“初始地图无解”，而是合法操作产生的不可恢复普通续局。若它是刻意的教学惩罚，需要清楚提示磨刃门槛，并把这两个负例送正式 Godot API 回放与 failure/solver 分类；若希望首店的三个按钮都代表有意义的开局选择，应由数据作者调整这个预算。审查没有自行修改平衡，也没有将此静态推导记为 Godot 测试通过。
