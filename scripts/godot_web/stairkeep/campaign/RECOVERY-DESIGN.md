## 不改难度即可使用的恢复能力

| 能力 | 现有API及效果 | 必须保留的边界 |
|---|---|---|
| 完整章节回档 | `restore_checkpoint(id)`；入口为1/4/7/10/13/16/19层，每个attempt只首次捕获。恢复当时全部资源、对象、门、库存、位置和日志。 | 相同seed/attempt；入口之后的收益与消耗一起回退，不能保留收益再恢复库存。未来时间线的checkpoint丢弃，历史failure/consumed IDs保留。入口可恢复不等于入口可赢。 |
| 同seed重开 | `restart_same_seed()`恢复第一层安全出生点、初始角色、全部世界与库存；当前seed、sequence、attempt不变。 | 放弃整局进度；不是给当前角色补血、退款或补货。失败历史不会被拿来重复推进seed。 |
| 完整存档读取 | `load_v2()`验证版本、内容、布局、状态、日志与checkpoint后整体提交。 | 校验失败不覆盖当前进度或原文件；旧三层v1不能静默变成21层进度。 |
| 受控新布局 | `respawn_new_variant(true, active_loss_id)`；只在当前未消费的失败事件上生效，序列推进一次，整局从第一层开始。 | 不是原seed恢复证据；不携带旧钥匙、已清对象、金币或库存。取消、陈旧loss ID和重复确认均不能推进序列。 |
| 取消拟购/购买保护 | 预览在clone实际购买后求解；取消或默认拦截known_losing不改变原campaign。unknown仍没有安全保证。 | 原界面尚未接入；取消拟购不是撤销已执行购买。已经购买后只能按完整回档/重开恢复，不能单项退款。 |

普通移动拒绝不可胜战斗，不会只因遇见强敌就宣布死亡。`assess_failure()`仅在完整跨层frontier无合法资源动作时记录`resource_exhausted`；有界未穷尽为unknown。`mark_loss_proven()`需要绑定当前实际状态的完整unsat receipt。**拟购clone的post-unsat receipt不能拿来冻结尚未购买的原局**。

显式致死挑战是另一条确认入口；它记录`combat_death/terminal_hp`，冻结base保留最后合法正生命等数值，不能把该元数据误写成base已经执行并扣完生命。重复展示同一失败不重复计数、不自动换seed。

## 26个晚期案例：已完成的恢复验证

每case保留原seed、原动作序列和定位哈希，实际CampaignRules重放到同一Base终态，核对HP/ATK/DEF、金币、钥匙、cleared对象和每店购买次数，再记录真实章节快照。599虽终点在F1，也必须按已到最终章的历史产生chapter19入口。

本批次采用以下验证顺序，不需先改变规则：

1. 对原终态做完整全局检查，保存失败类型和实际首领预览，不改原baseline。
2. 每个候选恢复实验用独立clone，从完整失败快照恢复chapter19；未找到赢路时再测16、13、10、7、4、1。各实验必须从同一原历史分支，不能把一次恢复试验的收益带到下一次。
3. 用正式API尝试明确替代后缀或有界solver；按实际库存逐条记录已清对象/已买offer的跳过，不把整条canonical后缀的预期资源硬塞入快照。
4. 有实际通关后缀才标`winning_suffix_replayed`；完整状态穷尽才标`unsatisfiable`；单条路线失败、预算耗尽或尚未执行都保留unknown/not-tested。若19层unknown但16层已赢，只能说「16层入口已验证」，不能说19层无解。
5. 另从每case实际初始checkpoint恢复，并在同seed实际重放完整blade路线，作为该case的从头恢复证据。它与「最近章节能救」分别计数。

结果表至少列出case index、seed、真实终点层/失败阶段、原失败状态哈希、checkpoint ID及完整状态哈希、恢复守恒检查、方法/预算、结果、实际胜利动作定位及原始失败定位。区分「最近可恢复入口」和「最近已实证有赢路入口」；后者不是全局最晚可赢入口的证明。

恢复后的整快照不能无条件要求等于旧checkpoint原字节：现有API保留原失败分支的`failure_events_seen/consumed_loss_ids`，并把checkpoint列表截到目标入口（含目标）；其余资源、对象、库存、日志、种子与失败状态按目标快照恢复。应据此构造完整expected snapshot再比较，而不是删除历史字段凑出「相等」。

| 已验证入口 | case数 | 结论 |
|---|---:|---|
| 第19层 | 10 | 这些case从实际末章入口恢复后已走出一条胜利路线。 |
| 第16层 | 13 | 当前有限尝试在较晚入口没有完成赢路证明；第16层实际后缀获胜，不表示第19层无解。 |
| 第13层 | 3 | 第13层实际后缀获胜；不排除较晚入口存在尚未找到的走法。 |

26个case还分别从各自真实初始checkpoint恢复，完成323事件blade路线，最终均为HP138 / ATK153 / DEF47 / 金币946。全体尝试包括180次作者ID顺序后缀不可执行、19次资源policy走到dead-end、19次有界solver unknown；它们是**尝试次数**，不是新增失败case，也不是入口无解证明。`proven_unsat=0`。

独立只读复核覆盖4个完整journal字节哈希、367条receipt定位、71份完整恢复树（45个候选入口及26个初始入口）、8,398个初始blade逐事件账本、43,989次初始路线实际动作及1,742次战斗比较。审查者没有重新启动引擎；实际动作来自根端Godot记录。

## 1,336个首店案例：拦截与因果分别证明

配对实验使用同一内容/规则/布局seed和原始action前缀，实际到达同一个购买前Base状态；Campaign额外日志/检查点另作绑定，不能要求原Base报告具有不存在的v2元数据。

| 对照分支 | 记录与可声称结论 |
|---|---|
| 原无guard分支 | 原价执行原购买和原后续actions，保留已观测失败与全部库存/路径证据。 |
| guard默认分支 | 在完全相同的拟购前状态查询、默认commit；known_losing拦截后完整原局不变。记录blocked/unknown/error各自分母。 |
| 显式接受控制分支 | 若实验需要验证经济未变，用新的明确确认ticket执行原购买，再重放原后续；这是控制分支，不计为guard救回。 |
| 新选择/恢复分支 | 取消后先核对可取金币、路线与实际可支付性；若合法且有验证，才选择edge，否则可用已验证完整回档，再实际验证新后缀。其actions已改变，单列为新策略/恢复结果，不能叫「原actions全部照旧却通关」。 |

默认拦截以后不能强行把原后续actions接上来：状态已经分叉。**拦下1,336次不等于让1,336局通关**，也不等于解决26个晚期案例。

本次正式全量已经分别完成这三个分支：1,336次production默认查询均为known_losing，默认拦截后完整状态不变；第二次fresh查询也均为known_losing，明确接受原购买后1,336次原败局终态复现；1,336次实际初始checkpoint整体恢复后，另走323事件blade路线实际通关。最后一项合计431,528个逐事件账本、2,260,474个记录的实际actions、89,512次preview／扣血比较；每case均保持原seed并结束于HP138 / ATK153 / DEF47 / 金币946。没有执行1,336条**当前购买前态**的winning suffix，不能以初始回档替代此因果证明。

正式汇总`output/recovery-followup-evidence-final/summary.json`绑定SHA256 `998332094d7592a69597cccfcfde1256ddf2aa4cd57934d89936462aacd86cac`。Early精确1,336、late精确26，各由4个无重无漏part组成；1,362次完整初始回档及其实际赢路完成。8个根端native worker均记录exit0、stderr0、source不变并已退出，最大并发4、BelowNormal；review者未启动引擎。完整逐case receipt为同目录`case-receipts.jsonl.gz`，SHA256 `2443137a5ff96b4f101d7fec6f546a256b9e62b9ba9d70f6fff20b71365409a4`。

独立只读审计重新核8份journal完整字节SHA、1,362个receipt精确index集合、全部early的默认前后完整快照／shadow实际购买快照、1,336份初始恢复整树及全部431,528个blade事件资源／库存／清除数量。Late receipt和4份manifest与此前已独立核过的26-case版本完全一致。详见[独立review](reviews/RECOVERY-FOLLOWUP-REVIEW.md)。这些结果仍不提供21层GUI／Web体验或50层成品证据。

保护提示不得承诺「取消后立即买edge」。预算独立审计在1,336例中找到82个原购买前仅24金币的`defense_door_open/flask`案例；其16金币入口拾取尚未取得。磨刃价格是28金币，默认拦截只保留这24金币，不会让磨刃自动变得可支付。应先检查未取金币/合法路线，或选择已验证的完整checkpoint回档。局部首店预算门槛可以解释拟购后的困难，但不能代替同一购买前态完整赢路证明。

该预算报告为任务工作区`output/early-purchase-budget-independent-review.json`，SHA256 `89c4034e43931ad56d0b8a20af52adb48277deec1d5a57ed2c769105f471d239`；本文件作者另只读核82条原raw byte SHA与before/after预算指针，没有将它记作新guard实跑或完整购买前赢路证明。

guard目前分析的是购买后状态。`post-unsat`只表示「拟购后无普通通关后缀」，不能单凭它说「这次购买把原本可赢的局变成必败」：

- 购买前有绑定的实际winning suffix，且拟购后完整unsat：才支持这一次选择关闭了该状态全部普通赢路。
- 购买前已完整unsat：本次购买后的unsat不是新增致败原因。
- 购买前未求解/unknown：因果保持未判定，即使guard可按post-unsat拦截。

若拟购edge后有真实winning suffix，可以把「原状态合法购买edge + 该后缀」组成购买前的赢路证人；必须绑定同一个实际前态。初始镜像存在赢路或另一前缀曾赢，不能替代这个前态证明。

## 可复核的中文提示草案

以下文案是backend条件与未来呈现的对应表，**不是已接入的GUI**。数值、库存、层号、checkpoint和分类必须来自同一个已绑定状态；未能完整判定时不能套用已确认败局的文本。

| 条件 | 标题 / 正文草案 | 可映射的现有操作 |
|---|---|---|
| 单场攻击不足 | **无法穿透护甲**。这场战斗不会执行，也没有扣除生命。可以查看升级或其他路线。 | 关闭预览、继续查看；不自动宣告整局失败。 |
| 单场生命不足 | **生命不足以赢下这场战斗**。预计损失{damage}，当前生命{hp}；战后至少要保留1点生命。尚未执行战斗。 | 返回；显式危险挑战是独立确认入口。 |
| 拟购known_losing | **购买后的资源无法完成这局**。分析已确认拟购后的进度没有通关路线。尚未购买，也未扣款。可以取消，或按原价明确确认购买。 | `cancel`；现backend也支持明确确认后`commit`。不写「这次购买一定是失败原因」。 |
| 取消拟购但替代升级尚不可支付 | **还不能购买磨刃**。磨刃需{price}金币，当前{gold}金币；本次保护没有扣款。可检查尚未取得的金币，或查看完整回档。未验证替代路线前，不保证当前进度可通关。 | 返回检查/查看已有checkpoint；不自动发金币、不展示必定可执行的“立即磨刃”。 |
| 拟购known_winning | **已验证一条通关路线**。这次购买后的状态存在已验证的后续走法；其他购物与战斗选择仍可能失败。尚未扣款。 | 取消或购买；不是「放心购买、之后随便玩」。 |
| 成功预览但unknown | **暂时无法判断**。本次分析未能确认购买后是否可通关。尚未扣款；继续购买不提供安全保证。 | 取消或按原规则提交现有unknown ticket。 |
| 查询额度用尽/未启动 | **本次分析未完成**。查询额度已用完，没有执行购买；这不能说明该购买安全或危险。 | 关闭/返回商店；没有ticket时不能假装调用了guard commit。后续UI流程另行接入。 |
| 当前完整资源败局 | **当前进度已无法继续**。已检查可到达的楼层，目前没有可获得的资源、可击败的敌人或可支付且有库存的升级。可以查看进度，或选择完整回档/重开。 | 完整checkpoint恢复、同seed重开、符合当前loss条件的新布局。 |
| 入口可恢复但未证可赢 | **可回到第{floor}层入口**。将恢复当时的完整进度；尚未确认这份入口状态能通关。 | 用户选择该checkpoint或查看更早入口。 |
| 入口实际后缀已赢 | **第{floor}层入口已有通关验证**。已验证这份入口状态存在一种通关走法，仍需作出相应资源选择。 | 该checkpoint恢复；可选查看已验证路线，不能自动替玩家执行。 |
| 确认完整回档 | **回到第{floor}层入口？** 此后的收益和消耗将一起回退；生命、金币、钥匙、怪物、物品和库存恢复到入口时，种子不变。 | `restore_checkpoint(id)`；放弃未来时间线的入口记录。 |
| 同seed重开 | **从这局起点重来？** 保留种子{seed}，从第一层初始资源重新开始，不保留本局后续收益。 | `restart_same_seed()`。 |
| 新布局重生 | **开始新的布局？** 将使用新种子{next_seed}从第一层重新开始，当前资源和已清关卡不会带入。 | 绑定当前loss ID的明确确认；陈旧/重复ID应提示未切换。 |

599可用的具体解释为：

> 塔心监守预计造成423点伤害，你当前有310点生命。要在战后至少保留1点生命，还需114点生命。可达商店的治疗库存已用完，剩余792金币目前无法补足生命。

严格条件为`HP > damage`，因此最低可胜生命是`damage + 1`；不能把423−310=113写成所需补给。同样，140损失/99生命至少需再补42生命。不得把封印哨兵的`damage=-1`当作负伤害或可回血。

599现有实际恢复证据是同seed `04f26220` 的第16层完整入口恢复后，以新资源选择实际通关、剩余68生命；其初始checkpoint另走blade通关剩余138生命。这不是向原310生命状态补发114生命，也不是保持原败局动作不变就通关。当前界面尚未提供这些按钮或路线展示，文案仍是待接入草案。

## 需要真实产品选择的分歧

现在不向用户发问题；26例与1,336例的正式全量均已完成。以下是后续真实产品界面或平衡决策，均未代用户选择，也不能靠悄改数据解决：

| 决策 | 方案A及影响 | 方案B及影响 | 何时才需要问 |
